# Scripts

This folder contains the executable scripts used to build the datasets and data artefacts required by the modelling stages of the TFM.

The scripts implement the reproducible **general data-preparation pipeline** from the raw ISIC 2024 SLICE-3D dataset up to:

- the final processed metadata;
- the preprocessed image Parquet dataset; and
- the official patient-level train, validation and test partitions for both
  modelling hypotheses (H1 and H2).

These artefacts constitute the common data foundation for **both tabular and
image modelling**.

> **Important:** The train/validation/test partitions generated by `split.py`
> are not exclusive to tabular modelling. They define the official
> patient-level partitions that must also be respected when preparing the
> image datasets for either traditional Machine Learning (ML) or Deep
> Learning (DL), so that experiments across data modalities remain directly
> comparable.

Image-specific representations such as PCA features and CNN embeddings are generated **after the general data-preparation pipeline**, from the preprocessed image Parquet dataset produced by `preprocess_images.py`. These representations belong specifically to the image-modelling branch and are not required for tabular modelling.

---

# Pipeline overview

The general data-preparation pipeline is:

```text
Raw ISIC 2024 SLICE-3D
        │
        ▼
1. preprocess_data.py
        │
        ▼
Interim metadata
        │
        ▼
2. final_preprocess_data.py
        │
        ▼
Final processed metadata
        │
        ├──────────────────────────────┐
        │                              │
        ▼                              ▼
3. preprocess_images.py           4. split.py
        │                              │
        ▼                              ▼
Preprocessed images             Patient-level splits
stored as Parquet                  for H1 and H2
        │                              │
        │                       ┌──────┼──────┐
        │                       ▼      ▼      ▼
        │                      Train   Val    Test
        │                              │
        │                     ┌────────┴────────┐
        │                     │                 │
        ▼                     ▼                 ▼
    Image branch      ML: Tabular models      Image branch:
        │                                     DL(CNN) - Image models
        │     Modelling Stage
        └───────────┐
                    │
                    ▼
        ┌───────────┴───────────┐
        ▼                       ▼
    PCA features      CNN embeddings
        │                       │
        └───────────┬───────────┘
                    ▼
           Traditional ML models
```

The important architectural distinction is that `preprocess_images.py` and `split.py` are parallel consumers of the final processed metadata.

`split.py` creates the official H1/H2 patient-level partitions, while `preprocess_images.py` creates the common preprocessed image Parquet dataset.

The four scripts above constitute the general data-preparation pipeline. The resulting H1/H2 patient-level splits are a common experimental constraint for both tabular and image modelling.

The image branch then derives PCA features and/or CNN embeddings from the preprocessed image Parquet dataset. These representations are used by traditional ML models, while the main Deep Learning branch operates directly on the preprocessed images.

# Requirements

Before running the pipeline, install the project dependencies and make sure
the project environment is synchronized:

```bash

```

All scripts should be executed from the project root using `uv`.

The same project environment should be used for the reproducible execution of the preprocessing pipeline and the subsequent modelling notebooks.

# Data preparation scripts

These scripts generate the metadata and image datasets used later for modelling.

Before running them, the raw ISIC 2024 SLICE-3D data must be downloaded from:

```text
https://challenge.isic-archive.com/data/#2024
```

The required dataset is: **ISIC 2024 SLICE-3D**.

The raw files should be placed as follows:

```text
data/raw/
├── metadata/
│   ├── ISIC_2024_Training_GroundTruth.csv
│   ├── ISIC_2024_Training_Supplement.csv
│   └── metadata.csv
│
└── images/
    ├── ISIC_XXXXXXX.jpg
    ├── ISIC_XXXXXXX.jpg
    └── ...
```

Images should be kept in the same format and naming convention as provided
by the original dataset.

---

## 1. `preprocess_data.py`

This is the first metadata-preparation stage. It generates the first preprocessed metadata dataset from the raw CSV files.

This script loads the raw metadata tables, merges the relevant sources, standardizes the main identifiers and variables, performs the first cleaning steps, and saves an interim Parquet dataset.

The output of this stage is subsequently consumed by `final_preprocess_data.py`.

Run:

```bash
uv run python scripts/preprocess_data.py
```

Expected output:

```text
data/interim/metadata/
└── preprocessed_from_raw_<timestamp>.parquet
```

The timestamp allows different executions of the preprocessing pipeline to coexist without overwriting previous artefacts.

---

## 2. `final_preprocess_data.py`

This is the final metadata-preparation stage before the modelling split or partitions
are created.

This script loads the latest interim metadata dataset generated by `preprocess_data.py`, applies the final preprocessing decisions required by the TFM, prepares the modelling targets, and saves the final processed metadata.

This dataset provides the common metadata foundation for:

- the H1 and H2 patient-level partitions;
- tabular modelling; and
- matching the image data with the corresponding modelling partitions.

If the required interim metadata file is not available, this script automatically runs `preprocess_data.py` first.

Run:

```bash
uv run python scripts/final_preprocess_data.py
```

Expected output:

```text
data/processed/metadata/
└── final_preprocessed_from_raw_<timestamp>.parquet
```

---

## 3. `preprocess_images.py`

This stage creates the **common preprocessed image dataset** used by the subsequent image-modelling branches.

The script loads the final processed metadata, matches each `lesion_id` with its corresponding raw JPG image, resizes the images to a fixed resolution, stores the resulting JPEG bytes inside Parquet files, and generates a JSON manifest describing the resulting image artefacts.

The output of this process is the **base image Parquet dataset** from which the subsequent image representations can be generated.

These representations include:

- PCA features for traditional ML models;
- embeddings generated by pretrained CNNs for traditional ML models; and, optionally, as an additional experiment, embeddings associated with CNN architectures for downstream modelling.

The preprocessed image Parquet dataset is also the intended input for the main Deep Learning branch, where CNN architectures can operate on the image data itself rather than on PCA vectors.

> **Important:** `preprocess_images.py` does not create the H1/H2
> train/validation/test partitions. Those partitions are generated by
> `split.py` from the final processed metadata. The image data used in each
> partition is subsequently selected or validated using the corresponding
> identifiers from the official patient-level splits.

If the final metadata file is not available, this script can automatically execute `final_preprocess_data.py` first.

### Recommended test

Before processing the complete image dataset, run a small test first:

```bash
uv run python scripts/preprocess_images.py --limit 1000
```

If the test completes successfully, run the full image preprocessing pipeline:

```bash
uv run python scripts/preprocess_images.py
```

Useful arguments:

```bash
--image-size 136
--shard-rows 500000
--jpeg-quality 95
--single-file
--limit 1000
```

Default behaviour:

```text
image size: 136 x 136
JPEG quality: 95
rows per shard: 500000
```

Expected output for a Single-file mode:

```text
data/interim/images/
├── raw_images_preprocessed_136_<timestamp>.parquet
└── raw_images_preprocessed_136_<timestamp>_manifest.json
```

Expected output for multiple shards:

```text
data/interim/images/
├── raw_images_preprocessed_136_<timestamp>_shard_000.parquet
├── raw_images_preprocessed_136_<timestamp>_shard_001.parquet
├── ...
└── raw_images_preprocessed_136_<timestamp>_manifest.json
```

The manifest records the files belonging to the generated image dataset and provides information required to identify the corresponding preprocessing run.

---

## 4. split.py

This is the final stage of the **general data-preparation pipeline**.

The script creates the train, validation and test partitions required for the modelling stage. The process generates the corresponding splits for the two modelling hypotheses:

```text
H1
├── train
├── validation
└── test

H2
├── train
├── validation
└── test
```

The split is performed at patient level, rather than independently at lesion level. Therefore, lesions belonging to the same patient remain in the same partition.

The target used for stratification is selected according to the corresponding hypothesis.

This patient-level partitioning is a fundamental experimental constraint of the TFM. The same patient must not appear in more than one partition.

The resulting H1/H2 partitions must be respected across all modelling modalities. This prevents patient-level data leakage and ensures that tabular and image experiments use equivalent train, validation and test populations.

The resulting H1/H2 partitions provide the common experimental basis for:

1. Traditional ML on tabular data
   - Logistic Regression
   - Random Forest
   - XGBoost
   - SVM
2. Traditional ML on image representations
   - PCA features
   - CNN-generated embeddings
3. Deep Learning on images
   - CNN architectures trained from the preprocessed image data.

For image modelling, the preprocessed image Parquet data, PCA features or CNN embeddings must be matched to the same H1/H2 patient-level partitions using their corresponding identifiers.

This ensures that tabular and image experiments use equivalent train, validation and test populations and that their results can be compared fairly.

```bash
uv run python scripts/split.py
```

* **Important**: Once the official TFM splits have been generated, modelling notebooks must use these existing H1/H2 train/validation/test partitions.

Individual modelling notebooks must not create new random train/test splits, because doing so would break the experimental comparability across models and modalities.

# Recommended workflow

The complete general data-preparation pipeline should be executed in the
following order:

* Step 1: Initial metadata preprocessing

```bash
uv run python scripts/preprocess_data.py
```

```text
data/interim/metadata/
└── preprocessed_from_raw_<timestamp>.parquet
```

* Step 2: Final metadata preprocessing

```bash
uv run python scripts/final_preprocess_data.py
```

```text
data/processed/metadata/
└── final_preprocessed_from_raw_<timestamp>.parquet
```

* Step 3: Image preprocessing

First validate the image-processing process on a small subset:

```bash
uv run python scripts/preprocess_images.py --limit 1000
```

If the test works correctly, run the full image preprocessing:

```bash
uv run python scripts/preprocess_images.py
```

Produces the base preprocessed image Parquet dataset and its manifest.

* Step 4: Train / validation / test split — H1/H2 patient-level partitions

Finally, `split.py` creates the official H1 and H2 train, validation and test
partitions at patient level while stratifying according to the corresponding
target.

```bash
uv run python scripts/split.py
```

```text
H1
├── train
├── validation
└── test

H2
├── train
├── validation
└── test
```

These partitions become the official experimental splits for the entire TFM, including both tabular and image modelling.

The execution order reflects the logical dependencies of the project. `preprocess_images.py` and `split.py` are both derived from the final processed metadata; neither script creates the other's output.

# Image representation stage

After the general data-preparation pipeline has been completed, the image branch can generate alternative representations from the preprocessed image Parquet dataset.

These processes are **not required for tabular modelling**.

## PCA representation

PCA can be applied to the preprocessed image data to create compact feature
vectors for traditional ML algorithms.

The resulting PCA features can subsequently be used by models such as:

```text
Logistic Regression
Random Forest
XGBoost
SVM
```

PCA is therefore a feature-engineering / dimensionality-reduction strategy for traditional ML on images.

It is not the input representation for the main CNN Deep Learning branch, because PCA converts the image into a vector representation and therefore does not preserve the original two-dimensional spatial structure required by a conventional CNN operating on images.

## CNN embeddings

Pretrained CNN architectures can also be used as frozen feature extractors to convert images into embedding vectors.

These embeddings can subsequently be used as input features for traditional ML algorithms such as:

```text
Logistic Regression
Random Forest
XGBoost
SVM
```

Different pretrained CNN architectures may produce different embedding spaces.

In this configuration, the CNN acts as a feature extractor and the downstream classifier is the traditional ML model. This is therefore different from training or fine-tuning a CNN as a Deep Learning classifier.

## Deep Learning CNN branch

The main Deep Learning image-modelling strategy is to train CNN architectures directly from the preprocessed image data generated by `preprocess_images.py`.

This branch does not require PCA or precomputed embeddings.

If computationally and methodologically useful, using precomputed CNN embeddings as input to a downstream model can be considered an additional experiment, but it is distinct from training the CNN itself end-to-end or through fine-tuning.

# Modelling architecture

The TFM evaluates classification models across two data modalities and two hypotheses.

## H1 and H2

Every modelling approach must be implemented for both:

```text
H1
H2
```

using the corresponding official patient-level train, validation and test partitions. The models must use the same official splits and common evaluation infrastructure so that their results are directly comparable.

## Tabular modelling

The final processed metadata is used directly as the basis for traditional ML models:

```text
Final metadata
      │
      ▼
Official H1/H2 splits
      │
      ├──────────────┐
      ▼              ▼
     H1             H2
      │              │
      ▼              ▼
┌───────────────┐ ┌───────────────┐
│ Logistic Reg. │ │ Logistic Reg. │
│ XGBoost       │ │ XGBoost       │
│ Random Forest │ │ Random Forest │
│ SVM           │ │ SVM           │
└───────────────┘ └───────────────┘
```

The same splits and evaluation methodology must be maintained across the
tabular models.

## Image modelling: Traditional ML

The preprocessed image Parquet dataset can be transformed into alternative
image-derived feature representations (PCA or CNN embeddings):

```text
Preprocessed images
        │
        ├───────────────┐
        ▼               ▼
       PCA       CNN embeddings
        │               │
        └───────┬───────┘
                ▼
          Traditional ML
       ┌────────┼────────┐
       ▼        ▼        ▼
     SVM        LR     XGBoost / Random Forest
```

These feature vectors can then be used as input to traditional ML models.

The resulting features must be matched to the official H1/H2 patient-level partitions before model training and evaluation.

## Image modelling: Deep Learning

The main Deep Learning branch operates directly on the preprocessed image data:

```text
Preprocessed images
        │
        ▼
   H1/H2 split IDs
        │
        ▼
      CNN
        │
        ▼
Prediction / probabilities
```

The CNN architectures can be trained or fine-tuned directly from the image data without requiring PCA.

Pretrained CNNs may optionally be used as a starting point through transfer learning and fine-tuning.

As an additional experiment, precomputed CNN embeddings may also be used as features for downstream models. This should be treated as a separate experimental configuration rather than as the primary CNN modelling path.

# Data leakage and experimental consistency

The train/validation/test partitions are generated at **patient level** and constitute a common experimental constraint across the entire TFM.

The same H1/H2 partitions must be respected for:

- tabular ML;
- traditional ML using image PCA features;
- traditional ML using CNN embeddings; and
- Deep Learning CNN models.

Conceptually:

```text
Official patient-level split
              │
      ┌───────┴────────┐
      ▼                ▼
Tabular data       Image data
      │                │
      │          match by IDs
      │                │
      └───────┬────────┘
              ▼
       H1 / H2 Train
       H1 / H2 Validation
       H1 / H2 Test
```

The same patient must never appear in more than one partition.

For any transformation that learns parameters from the TFM dataset, those parameters must be fitted only on the appropriate training data and then applied to validation and test data without refitting.

The test set must not be used for:
- model selection;
- hyperparameter tuning;
- feature-selection decisions;
- threshold selection; or
- any other training-related decision.

The purpose of maintaining identical partitions across modalities is to make comparisons between tabular and image models scientifically meaningful.

# Summary

The general data-preparation pipeline is:

```text
                    RAW DATA
                       │
                       ▼
             1. preprocess_data.py
                       │
                       ▼
              Interim metadata
                       │
                       ▼
          2. final_preprocess_data.py
                       │
                       ▼
             Final metadata
                       │
             ┌─────────┴─────────┐
             │                   │
             ▼                   ▼
  3. preprocess_images.py     4. split.py
             │                   │
             ▼                   ▼
       Image Parquet       H1/H2 patient-level
             │              Train / Val / Test
             │                   │
             │          ┌────────┴────────┐
             │          │                 │
             ▼          ▼                 ▼
       Image branch   Tabular ML      Image branch
             │                            │
             │                            ▼
             │                      Image CNN / DL
       ┌─────┴──────┐
       ▼            ▼
      PCA       CNN embeddings
       │            │
       └─────┬──────┘
             ▼
      Traditional ML
       SVM / LR / XGBoost / Random Forest

```

The key principle is:

The patient-level H1/H2 train, validation and test partitions generated by split.py are the common experimental partitions for the entire TFM, covering both tabular and image modelling.

The image Parquet generated by preprocess_images.py is the common image data source from which different image-modelling representations or architectures can be derived.

The modelling branches are therefore:

```text
TABULAR
Final metadata
     │
     ▼
H1/H2 official splits
     │
     ├── XGBoost / Random Forest
     ├── Logistic Regression
     └── SVM


IMAGE — TRADITIONAL ML
Image Parquet
     │
     ├── PCA
     │     └──► SVM / LR / XGBoost / Random Forest
     │
     └── CNN embeddings
           └──► SVM / LR / XGBoost / Random Forest


IMAGE — DEEP LEARNING
Image Parquet
     │
     ▼
H1/H2 official splits
     │
     ▼
CNN architectures
     │
     ▼
Deep Learning classification

     Optional experiment:
     CNN embeddings ───► downstream DL classifier model
```
The CNN-embedding configuration is an optional downstream experiment and should not be confused with training the CNN itself as a Deep Learning classifier.

All modelling approaches are implemented reproducibly for both H1 and H2 and evaluated using the common experimental and evaluation framework of the TFM.
